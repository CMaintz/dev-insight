## Purpose
Hosts the DevInsight HTTP API (middleware pipeline, endpoint mapping, wire contracts, error mapping) and owns sign-in: GitHub OAuth, a one-time code handoff to the SPA, stateless JWT sessions, and the signed-in user's profile (`backend/src/DevInsight.Api/Program.cs`, `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints`, `backend/src/DevInsight.Domain/Users/User.cs#User`).

## Features
- Sign in with GitHub: `GET /api/auth/github/login` redirects to GitHub, `GET /api/auth/github/callback` creates or updates the user and redirects to the SPA with a one-time code (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.StartGitHubSignIn`, `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.CompleteGitHubSignInAsync`).
- Exchange the one-time code for a bearer JWT, rate limited per user or IP at 20/min (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.ExchangeSignInCodeAsync`, `backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#ApiServices.AddRateLimits`).
- Get a fresh JWT while signed in via `POST /api/auth/token` (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.IssueTokenAsync`).
- Log out: `POST /api/auth/logout` returns 204 and the client discards its token (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.MapAuthEndpoints`, `frontend/src/app/core/auth/session.store.ts#SessionStore.logout`).
- Read the own profile (`GET /api/me`) and update bio, LinkedIn URL and portfolio visibility (`PUT /api/me/profile`) (`backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapProfile`, `backend/src/DevInsight.Application/Profile/ProfileUseCases.cs#ProfileUseCases`).
- Derive a user's commit-attribution identity (noreply addresses plus verified emails) for user-scope analysis (`backend/src/DevInsight.Domain/Users/User.cs#User.ToContributorIdentity`, `backend/src/DevInsight.Domain/Users/ContributorIdentity.cs#ContributorIdentity`).
- Frontend session: route guard on signed-in pages, token persisted in browser storage, sign-in redirect (`frontend/src/app/core/auth/auth.guard.ts#authGuard`, `frontend/src/app/core/auth/auth-token.store.ts#AuthTokenStore`, `frontend/src/app/core/auth/session.store.ts#SessionStore.signIn`).

## Owned entities
- `User`: GitHub id, login, name, email, avatar, bio, LinkedIn URL, portfolio flag, commit emails; created by `Register`, refreshed by `SyncWith`, edited by `UpdateProfile` (`backend/src/DevInsight.Domain/Users/User.cs#User`).
- `GitHubIdentity`: the GitHub account as reported by the API, input to user creation (`backend/src/DevInsight.Domain/Users/GitHubIdentity.cs#GitHubIdentity`).
- GitHub credential row (encrypted OAuth token): this slice is its only writer, during sign-in; the entity and its store are declared in backend-core (`backend/src/DevInsight.Infrastructure/Persistence/DevInsightDbContext.cs#GitHubCredential`, `backend/src/DevInsight.Infrastructure/Security/ProtectedGitHubCredentialStore.cs#ProtectedGitHubCredentialStore.SaveAsync`).
- Non-persisted: OAuth state cookie (10 min, encrypted with Data Protection) and one-time sign-in codes (60 s, in `IMemoryCache`) (`backend/src/DevInsight.Api/Auth/OAuthState.cs#OAuthState`, `backend/src/DevInsight.Api/Auth/SignInCodes.cs#SignInCodes`).

## Route registration
- Middleware order: forwarded headers, exception handler, status code pages, security headers, static files, CORS (only when `Frontend:Url` is an absolute origin), authentication, authorization, rate limiter (`backend/src/DevInsight.Api/Program.cs`, `backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#SecurityHeaders.UseSecurityHeaders`, `backend/src/DevInsight.Api/Auth/SignInCodes.cs#FrontendOptions.Origin`).
- OpenAPI, Scalar reference and `/health` are mapped in `backend/src/DevInsight.Api/Program.cs`; unknown `/api/*` paths return 404, every other path falls back to the SPA's `index.html` (`backend/src/DevInsight.Api/Program.cs`).
- `/api/auth`: `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.MapAuthEndpoints`.
- `/api/me` (authorized): `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapProfile`.
- `/api/repos`, `/api/analysis` (two groups), `/api/projects`, all requiring authorization: `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapRepositories`, `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapAnalysisRuns`, `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapAnalysisResults`, `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapProjects`.
- `/api/feedback/{id}`, `/api/dashboard` (authorized) and `/api/portfolio/{handle}` (anonymous allowed): `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapInsights`.
- Rate-limit policies `analysis` (30/min), `import` (5/min), `exchange` (20/min), partitioned by user id, else remote IP: `backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#ApiServices.PerUser`.
- Exceptions map to problem details: `NotFoundException` 404, `DomainException` 400, `BadHttpRequestException` its status, `PreconditionFailedException` 412 (`backend/src/DevInsight.Api/Infrastructure/ProblemDetailsExceptionHandler.cs#ProblemDetailsExceptionHandler.TryHandleAsync`).
- Wire contracts and domain-to-DTO mapping: `backend/src/DevInsight.Api/Contracts/Dtos.cs`, `backend/src/DevInsight.Api/Contracts/Mapping.cs#Mapping`.

## Happy paths

### GitHub sign-in from the SPA to a stored user and a JWT
1. Entrypoint: `SessionStore.signIn` sends the browser to `/api/auth/github/login?returnUrl=...`, with the return URL restricted to a local path (`frontend/src/app/core/auth/session.store.ts#SessionStore.signIn`, `frontend/src/app/core/auth/session.store.ts#safeReturnUrl`).
2. The API sanitizes the return URL (default `/dashboard`), generates a random state, stores state plus return URL in an encrypted HttpOnly cookie scoped to `/api/auth`, and redirects to GitHub's authorize URL with scopes `read:user`, `user:email` and, if configured, `repo` (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.StartGitHubSignIn`, `backend/src/DevInsight.Api/Auth/OAuthState.cs#OAuthState.Begin`, `backend/src/DevInsight.Api/Auth/OAuthState.cs#OAuthState.SanitizeReturnUrl`, `backend/src/DevInsight.Infrastructure/GitHub/OctokitGitHubGateway.cs#OctokitGitHubGateway.GetAuthorizationUrl`).
3. GitHub calls back to `/api/auth/github/callback`; the state is compared to the cookie in constant time and the cookie deleted; a mismatch or missing code redirects to the SPA's `/auth/callback?error=signin_failed` (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.CompleteGitHubSignInAsync`, `backend/src/DevInsight.Api/Auth/OAuthState.cs#OAuthState.Complete`, `backend/src/DevInsight.Api/Auth/SignInCodes.cs#FrontendOptions.CallbackUrl`).
4. `LoginWithGitHub` exchanges the code for a GitHub token, fetches the user and verified emails, then finds the user by GitHub id and either registers a new `User` or syncs the existing one (`backend/src/DevInsight.Application/Auth/LoginWithGitHub.cs#LoginWithGitHub.ExecuteAsync`, `backend/src/DevInsight.Infrastructure/GitHub/OctokitGitHubGateway.cs#OctokitGitHubGateway.ExchangeCodeForTokenAsync`, `backend/src/DevInsight.Infrastructure/GitHub/OctokitGitHubGateway.cs#OctokitGitHubGateway.GetIdentityAsync`, `backend/src/DevInsight.Infrastructure/Persistence/Stores/EfStores.cs#EfUserStore.FindByGitHubIdAsync`, `backend/src/DevInsight.Domain/Users/User.cs#User.Register`, `backend/src/DevInsight.Domain/Users/User.cs#User.SyncWith`).
5. Persistence: the GitHub token is encrypted with Data Protection into the credential row, then one `SaveChangesAsync` on the DbContext commits user and credential (`backend/src/DevInsight.Infrastructure/Security/ProtectedGitHubCredentialStore.cs#ProtectedGitHubCredentialStore.SaveAsync`, `backend/src/DevInsight.Infrastructure/Persistence/DevInsightDbContext.cs#DevInsightDbContext`).
6. The callback issues a 60 s single-use code bound to the user id and redirects to the SPA's `/auth/callback?code=...&returnUrl=...` (`backend/src/DevInsight.Api/Auth/SignInCodes.cs#SignInCodes.Issue`, `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.CompleteGitHubSignInAsync`).
7. The SPA callback page posts the code to `/api/auth/exchange` (`frontend/src/app/features/auth-callback/auth-callback.page.ts#AuthCallbackPage.complete`, `frontend/src/app/core/api/auth.api.ts#AuthApi.exchange`).
8. The API redeems the code atomically (400 problem if unknown, expired or used), loads the user and signs an HS256 JWT with `sub` = user id, `unique_name` = login, a random `jti`, default lifetime 7 days, returned as `{ accessToken, expiresAt }` (`backend/src/DevInsight.Api/Auth/SignInCodes.cs#SignInCodes.Redeem`, `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.IssueTokenAsync`, `backend/src/DevInsight.Api/Auth/SessionTokens.cs#SessionTokenIssuer.Issue`, `backend/src/DevInsight.Api/Auth/SessionTokens.cs#JwtOptions`, `backend/src/DevInsight.Api/Contracts/Dtos.cs#TokenDto`).
9. The SPA stores the token in a signal and browser storage under `devinsight.token`, reloads the session profile and navigates to the return URL (`frontend/src/app/core/auth/auth-token.store.ts#AuthTokenStore.set`, `frontend/src/app/core/auth/session.store.ts#SessionStore.refresh`).

### Authenticated request through the pipeline
1. Entrypoint: an SPA call to `/api/*`; the bearer interceptor adds `Authorization: Bearer <token>` and the base-URL interceptor rewrites the URL when the API is on another origin (`frontend/src/app/core/http/api.interceptors.ts#bearerTokenInterceptor`, `frontend/src/app/core/http/api.interceptors.ts#apiBaseUrlInterceptor`, `frontend/src/app/app.config.ts`).
2. For a cross-origin SPA, the default CORS policy allows only the configured frontend origin, `Authorization`/`Content-Type` headers, and exposes `Location` (`backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#ApiServices.AddCrossOriginSpa`).
3. JWT bearer authentication validates issuer, audience and signing key with 1 min clock skew and keeps raw claim names (`MapInboundClaims = false`) (`backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#ApiServices.AddJwtBearer`).
4. Groups with `RequireAuthorization` reject anonymous callers; the handler receives `CurrentUser`, bound from the `sub` claim (`backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapApiEndpoints`, `backend/src/DevInsight.Api/Auth/CurrentUser.cs#CurrentUser.BindAsync`, `backend/src/DevInsight.Api/Auth/SessionTokens.cs#ClaimsPrincipalExtensions.GetUserId`).
5. Rate-limited routes partition by that user id (`backend/src/DevInsight.Api/Infrastructure/ApiServices.cs#ApiServices.PerUser`); domain and not-found exceptions become problem details (`backend/src/DevInsight.Api/Infrastructure/ProblemDetailsExceptionHandler.cs#ProblemDetailsExceptionHandler.TryHandleAsync`).
6. On a 401 from any non-public path, the SPA clears the token, marks the session signed out and navigates to `/` (`frontend/src/app/core/http/error.interceptor.ts#errorInterceptor`, `frontend/src/app/core/auth/session.store.ts#SessionStore.markSignedOut`).

### Profile read and update
1. Entrypoint (read): `authGuard` calls `SessionStore.ensureLoaded`, which issues one `GET /api/me` probe; a 401 clears the stored token and the guard redirects to `/` (`frontend/src/app/core/auth/auth.guard.ts#authGuard`, `frontend/src/app/core/auth/session.store.ts#SessionStore.ensureLoaded`, `frontend/src/app/core/api/profile.api.ts#ProfileApi.me`).
2. The API loads the user by id or throws `NotFoundException` (404), and maps it to `ProfileDto` with `portfolioPath = /u/{login}` (`backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapProfile`, `backend/src/DevInsight.Application/Profile/ProfileUseCases.cs#ProfileUseCases.GetAsync`, `backend/src/DevInsight.Infrastructure/Persistence/Stores/EfStores.cs#EfUserStore.GetAsync`, `backend/src/DevInsight.Api/Contracts/Mapping.cs#Mapping.ToDto`).
3. Entrypoint (update): the settings page submits `PUT /api/me/profile` (`frontend/src/app/features/settings/settings.page.ts#SettingsPage.submit`, `frontend/src/app/core/api/profile.api.ts#ProfileApi.update`).
4. `User.UpdateProfile` trims the bio (max 2000 chars), requires an https `linkedin.com` URL, sets the portfolio flag and `UpdatedAt`; violations raise `DomainException` (400) (`backend/src/DevInsight.Application/Profile/ProfileUseCases.cs#ProfileUseCases.UpdateAsync`, `backend/src/DevInsight.Domain/Users/User.cs#User.UpdateProfile`, `backend/src/DevInsight.Domain/Users/User.cs#User.NormalizeLinkedInUrl`).
5. Persistence: `SaveChangesAsync` on the unit of work; the SPA puts the returned profile into the session store (`backend/src/DevInsight.Application/Profile/ProfileUseCases.cs#ProfileUseCases.UpdateAsync`, `frontend/src/app/core/auth/session.store.ts#SessionStore.setProfile`).

- How does the SPA react when the 7-day JWT expires, other than the generic 401 handling? No refresh flow was found in `frontend/src/app/core/auth`.

- What does the callback return when GitHub rejects the code? `ExchangeCodeForTokenAsync` throws `InvalidOperationException`, which `ProblemDetailsExceptionHandler` does not map (`backend/src/DevInsight.Infrastructure/GitHub/OctokitGitHubGateway.cs#OctokitGitHubGateway.ExchangeCodeForTokenAsync`).
