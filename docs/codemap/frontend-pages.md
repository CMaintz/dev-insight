## Purpose
The Angular pages that are not a domain of their own (landing, GitHub sign-in callback, single repository detail, profile settings, not-found), lazy-loaded from `frontend/src/app/app.routes.ts#routes`, plus the shared UI components, chart components, formatters, form validators, signal utilities and global SCSS partials that every feature page reuses (`frontend/src/app/shared`, `frontend/src/styles`).

## Features
- Landing at `/`: marketing steps and the three score dimensions with weights from `frontend/src/app/shared/format/metrics.ts#DIMENSION_WEIGHTS`; a signed-out visitor starts GitHub sign-in via `frontend/src/app/features/landing/landing.page.ts#LandingPage.signIn`, a signed-in one gets a link to `/dashboard` (`frontend/src/app/features/landing/landing.page.html`).
- Sign-in completion at `/auth/callback`: exchanges the one-time `code` for a bearer token, shows a failure card with retry when GitHub denied access, the code is missing, or the exchange fails (`frontend/src/app/features/auth-callback/auth-callback.page.ts#AuthCallbackPage`).
- Repository detail at `/repositories/:id` (behind `frontend/src/app/core/auth/auth.guard.ts#authGuard`): repository facts, latest analysis scores, metric breakdown, activity/score-history/language charts, largest files and feedback split into improvements and strengths, for either scope (`frontend/src/app/features/repository-detail/repository-detail.page.ts#RepositoryDetailPage`, `frontend/src/app/features/repository-detail/feedback-list.ts#FeedbackList`, `frontend/src/app/features/repository-detail/metric-breakdown.ts#MetricBreakdown`, `frontend/src/app/shared/ui/scope-toggle.ts#ScopeToggle`).
- Trigger an analysis of the repository from the detail page, with in-progress state and automatic reload of results when runs settle (`frontend/src/app/features/repository-detail/repository-detail.page.ts#RepositoryDetailPage.analyse`, `frontend/src/app/shared/util/reload-on.ts#reloadOn`).
- Profile settings at `/settings`: edit bio (max `frontend/src/app/features/settings/settings.page.ts#BIO_MAX` chars), LinkedIn URL (https on `linkedin.com` or a subdomain, `frontend/src/app/shared/forms/validators.ts#linkedInUrlValidator`) and portfolio visibility, and see a link to the public portfolio path (`frontend/src/app/features/settings/settings.page.ts#SettingsPage`).
- Not-found catch-all at `**` with a link back to `/` (`frontend/src/app/features/not-found/not-found.page.ts#NotFoundPage`).
- Shared building blocks used by other feature slices: UI components such as `frontend/src/app/shared/ui/empty-state.ts#EmptyState`, `frontend/src/app/shared/ui/score-breakdown.ts#ScoreBreakdown`, `frontend/src/app/shared/ui/kpi-tile.ts#KpiTile` and `frontend/src/app/shared/ui/workspace-actions-bar.ts#WorkspaceActionsBar`; charts in `frontend/src/app/shared/charts/charts.ts` fed by mappers in `frontend/src/app/shared/charts/chart-data.ts`; formatters in `frontend/src/app/shared/format/format.ts`; `frontend/src/app/shared/util/busy-flag.ts#BusyFlag` (re-entrancy guard for async actions); `frontend/src/app/shared/util/browser-storage.ts` (localStorage access that swallows failures).
- Global styles: `frontend/src/styles.scss` pulls in `frontend/src/styles/_layout.scss`, `frontend/src/styles/_controls.scss` and `frontend/src/styles/_charts.scss`, which share `frontend/src/styles/_mixins.scss`.

## Owned entities
No server data. Client state owned by the slice's components:
- The callback page's `phase` (`working` | `failed`) and error `message` signals (`frontend/src/app/features/auth-callback/auth-callback.page.ts#AuthCallbackPage`).
- The settings reactive form built by `frontend/src/app/features/settings/settings.page.ts#createProfileForm` and mapped to the API payload by `frontend/src/app/features/settings/settings.page.ts#toProfileUpdate` (blank strings become `null`).
- The bearer token is written by this slice's callback page but owned by core: `frontend/src/app/core/auth/auth-token.store.ts#AuthTokenStore` (localStorage key `devinsight.token`). The analysis scope shown on the detail page lives in `frontend/src/app/core/scope/scope-preference.ts#ScopePreference`.

## Happy paths
### Sign in with GitHub
1. Entrypoint: the landing page's sign-in button calls `frontend/src/app/features/landing/landing.page.ts#LandingPage.signIn`, which calls `frontend/src/app/core/auth/session.store.ts#SessionStore.signIn` with `/dashboard`; that assigns the browser location to `/api/auth/github/login?returnUrl=...` (`frontend/src/app/core/auth/session.store.ts#gitHubLoginUrl`).
2. Backend redirects to GitHub (`backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.StartGitHubSignIn`); GitHub's callback runs `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.CompleteGitHubSignInAsync`, which calls `backend/src/DevInsight.Application/Auth/LoginWithGitHub.cs#LoginWithGitHub.ExecuteAsync`: registers or syncs the `User`, saves the GitHub access token via `IGitHubCredentialStore`, and commits the unit of work. It then issues a one-time code held in memory cache (`backend/src/DevInsight.Api/Auth/SignInCodes.cs#SignInCodes.Issue`) and redirects to the SPA's `/auth/callback?code=...&returnUrl=...` (`backend/src/DevInsight.Api/Auth/SignInCodes.cs#FrontendOptions.CallbackUrl`).
3. `/auth/callback` loads `frontend/src/app/features/auth-callback/auth-callback.page.ts#AuthCallbackPage`; query params bind to its `code`/`returnUrl`/`error` inputs through `withComponentInputBinding` in `frontend/src/app/app.config.ts#appConfig`.
4. `frontend/src/app/features/auth-callback/auth-callback.page.ts#AuthCallbackPage.complete` posts the code via `frontend/src/app/core/api/auth.api.ts#AuthApi.exchange` (`POST /api/auth/exchange`, errors silenced from global toasts). Backend `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.ExchangeSignInCodeAsync` redeems the code (`backend/src/DevInsight.Api/Auth/SignInCodes.cs#SignInCodes.Redeem`) and returns a JWT from `backend/src/DevInsight.Api/Endpoints/AuthEndpoints.cs#AuthEndpoints.IssueTokenAsync`; nothing is written to the database in this step.
5. The page stores the token (`frontend/src/app/core/auth/auth-token.store.ts#AuthTokenStore.set`, persisted to localStorage), reloads the session via `frontend/src/app/core/auth/session.store.ts#SessionStore.refresh` (`GET /api/me`), and navigates to `frontend/src/app/core/auth/session.store.ts#safeReturnUrl` with `replaceUrl`. Later API calls carry the token via `frontend/src/app/core/http/api.interceptors.ts#bearerTokenInterceptor`.

### View and analyse a repository
1. Entrypoint: `/repositories/:id` under `frontend/src/app/core/auth/auth.guard.ts#authGuard` loads `frontend/src/app/features/repository-detail/repository-detail.page.ts#RepositoryDetailPage`; `id` is a required route input.
2. Reads: `frontend/src/app/core/api/repos.api.ts#ReposApi.repoResource` (`GET /api/repos/{id}`), plus `frontend/src/app/core/api/analysis.api.ts#AnalysisApi.latestResource` (`GET /api/analysis/{id}?scope=`) and `frontend/src/app/core/api/analysis.api.ts#AnalysisApi.historyResource` (`GET /api/analysis/{id}/history?scope=`), keyed on id and the scope toggled by `frontend/src/app/shared/ui/scope-toggle.ts#ScopeToggle`. A 404 on the analysis shows the "not analysed" empty state (`frontend/src/app/core/http/problem-details.ts#isNotFound`). Backend handlers are in `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapRepositories` and `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapAnalysisResults`.
3. The Analyse button calls `frontend/src/app/features/repository-detail/repository-detail.page.ts#RepositoryDetailPage.analyse` -> `frontend/src/app/core/analysis/workspace-actions.ts#WorkspaceActions.analyseRepository` -> `frontend/src/app/core/analysis/run-tracker.ts#RunTracker.analyse`, which posts one run per scope (`repo` and `user`) via `frontend/src/app/core/api/analysis.api.ts#AnalysisApi.run` (`POST /api/analysis/run/{id}?scope=`).
4. Backend `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapAnalysisRuns` calls `backend/src/DevInsight.Application/Analyses/RequestAnalysis.cs#RequestAnalysis.ExecuteAsync`: returns an existing unfinished run for that repository and scope, otherwise persists a new `backend/src/DevInsight.Domain/Analyses/AnalysisRun.cs#AnalysisRun.Queue` run, saves, and enqueues its id on `IAnalysisQueue`; responds 202.
5. The tracker polls each run (`frontend/src/app/core/analysis/run-poller.ts`, `GET /api/analysis/runs/{runId}`) and bumps `frontend/src/app/core/analysis/run-tracker.ts#RunTracker.settledCount` when a run finishes; the page's `frontend/src/app/shared/util/reload-on.ts#reloadOn` hooks reload the latest analysis and history on each bump.

### Save profile settings
1. Entrypoint: `/settings` under `frontend/src/app/core/auth/auth.guard.ts#authGuard` loads `frontend/src/app/features/settings/settings.page.ts#SettingsPage`, whose form is seeded from `frontend/src/app/core/auth/session.store.ts#SessionStore.profile`.
2. Submit runs `frontend/src/app/features/settings/settings.page.ts#SettingsPage.submit`: validates, maps with `frontend/src/app/features/settings/settings.page.ts#toProfileUpdate`, and sends `frontend/src/app/core/api/profile.api.ts#ProfileApi.update` (`PUT /api/me/profile`) under a `BusyFlag`, with 404 surfaced as a "sign in again" message (`frontend/src/app/core/http/surfaced-errors.ts#UserActionErrors`).
3. Backend `backend/src/DevInsight.Api/Endpoints/ApiEndpoints.cs#ApiEndpoints.MapProfile` calls `backend/src/DevInsight.Application/Profile/ProfileUseCases.cs#ProfileUseCases.UpdateAsync`, which applies `backend/src/DevInsight.Domain/Users/User.cs#User.UpdateProfile` (bio, LinkedIn URL, portfolio visibility) and saves the unit of work, returning the updated profile.
4. On success the page writes the returned profile into `frontend/src/app/core/auth/session.store.ts#SessionStore.setProfile`, marks the form pristine and shows a success toast via `frontend/src/app/core/notifications/toast.service.ts#ToastService`.
